# Ciderd Implementation Plan

**Goal:** Implement the supplied macOS daemon guide as a reusable `ciderd`
library and a `ciderd` binary in a root Cargo workspace.

**Architecture:** A single state owner publishes immutable snapshots through a
watch channel. Independently scheduled collectors use bounded supervised
processes; HTTPS sends read published memory. Acquisition and parsing stay
separate. The binary provides enrollment, configuration validation, foreground
execution, and restricted native worker operations.

**Spec:** `crates/ciderd/contract/guide.org`, imported from the user's
`~/Downloads/macos-storage-rust-daemon-guide` bundle.

**Global constraints:** Heartbeat schema 2.0; exact decimal-string integers;
latest-state delivery; authenticated HTTPS; no redirects; retained child
ownership and permits through actual exit; no automatic destructive diagnostics;
macOS-specific calls confined to the platform boundary. Preserve the existing
web interface and the user's pending environment changes.

## Task 1: Configuration, contract, and state

- [x] Import supplied schemas, catalog, synthetic fixtures, and deployment samples.
- [x] Add workspace/package with explicit library and binary targets.
- [x] Test strict config and wire parsing, exact wide integers, immutable repeated
  observations, partial updates, inventory/evidence acknowledgements and limits.
- [x] Implement typed domain records, validation, single-owner state and snapshots.

## Task 2: Persistent identity and bounded command workers

- [x] Test enrollment, monotonically increasing generation, single instance,
  corrupt/missing identity rejection, deadlines and output floods.
- [x] Implement atomic metadata writes, active-job records and conservative
  restart accounting. No asynchronous send waits for persistence.
- [x] Implement command supervision with independent pipe caps, deadlines,
  retained reapers, per-class limits and per-scope admission.

## Task 3: Acquisition and scheduling

- [x] Implement pure adapters for diskutil/APFS, SMART and NFS counter fixtures.
- [x] Implement native cached mount enumeration, isolated capacity, IOKit and
  SDK-backed NFS status where the target SDK supports it.
- [x] Exercise real local acquisition with bounded smoke checks; record source
  versions and unsupported capabilities explicitly.
- [x] Schedule independent collectors with skipped missed ticks, generation
  checks, jitter and bounded shutdown.

## Task 4: Heartbeat transport, CLI and verification

- [x] Test HTTP acknowledgements, failures, byte limits, retry policy and sender
  progress while collectors stall using a local test peer.
- [x] Wire secure transport, enrollment/validate/run/worker CLI and deployment docs.
- [x] Run Cargo format, tests, Clippy and binary build; validate emitted heartbeat
  against supplied schema and complete a foreground start/stop smoke test.
- [x] Review correctness and document any optional platform coverage limitations.

No install, launchd registration, remote telemetry submission or repository
commit is needed to make this implementation reviewable.


## Completion evidence — 2026-09-12

- Pinned Nix development shell: Rust 1.97.1 on Apple Silicon macOS.
- `cargo test --workspace --locked`: 83 passed; three ignored child-helper entry
  points are exercised by the command supervision tests as subprocesses.
- `cargo fmt --all -- --check`, Clippy with `-D warnings`, and the release binary
  build passed in the pinned shell.
- Supplied Python contract validator passed: 71 catalog definitions, four
  heartbeat fixtures, acknowledgement checks, and 21 invalid-input cases.
- Release `snapshot --seconds 3`: supplied JSON Schema accepted 41 resources,
  22 relationships and 54 collections from local acquisition.
- Release CLI validation, enrollment, two foreground runs and SIGTERM shutdown
  passed with a local test endpoint. Generation advanced from 1 to 2; both runs
  exited in about 1.01 seconds and reaped every admitted worker.
- Independent scoped review confirmed the final tombstone, mount incarnation,
  CA ownership, enrichment lifecycle, persistence retry and SMART epoch fixes.

Target-environment limits remain documented in the crate README: successful
NSTATUS on a real NFS mount, Intel macOS, installed launchd operation and signed
packaging are not verified. Persistent physical identity and Disk Arbitration
event enrichment remain future work; optional probes/diagnostics are disabled.
